4.1 PHƯƠNG ÁN CÀI ĐẶT VÀ CHUYỂN ĐỔI HỆ THỐNG

4.1.1 Phương án cài đặt hệ thống mới

Hệ thống MotoShop CRM được xây dựng theo kiến trúc 3 tầng (3-Tier Architecture) hiện đại gồm Tầng trình diễn (React 19 Single Page Application), Tầng xử lý nghiệp vụ (ASP.NET Core Web API .NET 10) và Tầng cơ sở dữ liệu (Microsoft SQL Server 2022). Quá trình cài đặt mới hệ thống tại showroom được thực hiện theo quy chuẩn sau:

1. Yêu cầu cấu hình phần cứng & phần mềm

Thành phần Cấu hình tối thiểu (Minimum) Cấu hình khuyến nghị (Recommended)
Máy chủ Showroom (Server) CPU 4 cores, RAM 8GB, SSD 120GB CPU Intel Core i7 / Xeon 8 cores, RAM 16GB, SSD NVMe 512GB
Máy trạm nhân viên (Client POS) CPU Intel Core i3, RAM 4GB, Màn hình 1366x768 CPU Intel Core i5, RAM 8GB, Màn hình Full HD 1920x1080
Hệ điều hành Windows 10 Pro 64-bit Windows 11 Pro 64-bit / Windows Server 2022 Datacenter
Môi trường thực thi .NET Runtime 8.0/10.0, Node.js 18.x LTS, SQL Server 2019 .NET SDK 10.0, Node.js 22.x LTS, SQL Server 2022 Express/Standard
Trình duyệt Web Google Chrome 110+, Microsoft Edge 110+ Bản Chrome / Edge mới nhất (hỗ trợ hiển thị canvas QR và Recharts)

2. Quy trình cài đặt step-by-step

Bước 1: Khởi tạo Cơ sở dữ liệu SQL Server

  • Mở SQL Server Management Studio (SSMS), kết nối tới máy chủ localhost.
  • Chạy tập tin kịch bản d:\crm-project\init-db\init.sql để tạo CSDL CRM_XeMayPhuTung, toàn bộ cấu trúc 12 bảng thực thể và nạp dữ liệu mẫu ban đầu (tài khoản, danh mục xe máy, kho phụ tùng chính hãng).

Bước 2: Cấu hình Backend ASP.NET Core API

  • Mở tập tin CrmBackend\appsettings.json, kiểm tra chuỗi kết nối: 
    {
  "ConnectionStrings": {
    "DefaultConnection": "Server=localhost;Database=CRM_XeMayPhuTung;Integrated Security=True;TrustServerCertificate=True;"
  }
}
  • Kiểm tra cổng API tại Properties\launchSettings.json: Chạy tại cổng http://localhost:5208.

Bước 3: Khởi động tự động hệ thống bằng 1-Click

  • Nhấp đúp chuột vào tập tin điều phối tự động: D:\crm-project\CHAY_DO_AN.bat.
  • Tập tin sẽ tự động mở 2 tiến trình chạy độc lập: Backend API (:5208) và Frontend React (:5173), đồng thời tự bật trình duyệt truy cập ngay vào hệ thống.

4.1.2 Phương án chuyển đổi từ hệ thống cũ sang hệ thống mới

Trước khi đưa MotoShop CRM vào vận hành, showroom đang quản lý việc bán xe, đặt cọc và dịch vụ sửa chữa thông qua sổ sách giấy truyền thống kết hợp các bảng tính Microsoft Excel phân tán (gồm file theo dõi cọc, sổ bảo hành giấy 3 năm và phiếu sửa chữa xưởng). Để chuyển đổi sang hệ thống mới, nhóm đề xuất phương án chuyển đổi khoa học như sau:

1. Đánh giá và lựa chọn chiến lược chuyển đổi

Chiến lược Đặc điểm vận hành Ưu điểm Nhược điểm & Đánh giá
Chuyển đổi trực tiếp (Direct Cutover) Dừng hoàn toàn hệ thống cũ, kích hoạt ngay hệ thống mới tại một thời điểm. Chi phí thấp, nhanh gọn. Rủi ro rất cao nếu nhân viên chưa quen hoặc có sự cố kỹ thuật xảy ra trong giờ cao điểm.
Chuyển đổi song song (Parallel Conversion)
★ ĐƯỢC CHỌN		 Vận hành song song hệ thống cũ và MotoShop CRM mới trong thời gian 02 đến 04 tuần. An toàn tuyệt đối, dữ liệu được đối soát chéo 100%, không gián đoạn việc nhận xe của khách. Tăng khối lượng công việc nhập liệu tạm thời cho nhân viên trong giai đoạn song hành.
Chuyển đổi thí điểm (Pilot Conversion) Áp dụng trước tại 1 quầy hoặc 1 chi nhánh thử nghiệm. Khoanh vùng rủi ro tốt. Phù hợp với chuỗi đại lý lớn nhiều chi nhánh, quy mô 1 showroom độc lập chưa cần thiết.
Chuyển đổi từng giai đoạn (Phased)
★ KẾT HỢP		 Triển khai trước phân hệ Khách hàng CRM → Bán xe cọc → Xưởng dịch vụ. Nhân viên dễ thích nghi từng bước. Được lựa chọn kết hợp cùng phương án song song.
Phương án tối ưu được lựa chọn: Áp dụng Chuyển đổi song song kết hợp từng giai đoạn (Phased Parallel Conversion) trong 30 ngày. Tuần 1-2 đưa phân hệ Xem xe & Quản lý Khách hàng vào hoạt động; tuần 3-4 kích hoạt đầy đủ phân hệ Cọc xe VietQR, Sổ bảo hành điện tử và Nghiệm thu bàn nâng xưởng.

2. Kế hoạch di chuyển dữ liệu (Data Migration - ETL)

  • Trích xuất (Extract): Xuất toàn bộ danh sách khách hàng, công nợ, lịch sử bảo dưỡng và kho phụ tùng từ các file Excel cũ (danh_sach_khach_hang.xlsx, nhan_vien_ban_hang.xlsx).
  • Làm sạch & Chuẩn hóa (Transform): Định dạng lại số điện thoại chuẩn 10 chữ số, chuẩn hóa mã số định danh CCCD, loại bỏ các bản ghi trùng lặp và phân loại hạng CLV ban đầu (Đồng/Bạc/Vàng) dựa trên tổng chi tiêu lịch sử.
  • Nạp dữ liệu (Load): Dùng kịch bản SQL Bulk Insert để nạp trực tiếp vào các bảng KHACH_HANG, XE_KHACH_HANG, PHU_TUNG đảm bảo toàn vẹn khóa ngoại.

4.2 PHƯƠNG ÁN BẢO MẬT, SAO LƯU VÀ PHỤC HỒI CƠ SỞ DỮ LIỆU

4.2.1 Chính sách bảo mật hệ thống toàn diện

Phạm vi bảo mật Cơ chế kỹ thuật triển khai Mục tiêu bảo vệ
Phân quyền truy cập (RBAC) Phân định 4 vai trò rõ rệt: SuperAdmin, NhanVienBanHang, NhanVienKyThuat, KhachHang. Kiểm tra quyền tại API Controllers và React Route Guards. Chống truy cập trái phép, nhân viên xưởng không xem được doanh thu cấp giám đốc.
Bảo mật CSDL & Chống tấn công Sử dụng tham số hóa truy vấn 100% qua Micro-ORM Dapper (new { Id = id }), không nối chuỗi SQL thủ công. Triệt tiêu hoàn toàn nguy cơ tấn công SQL Injection.
Bảo mật giao tiếp (API Security) Cấu hình CORS Policy nghiêm ngặt tại Program.cs, chỉ chấp nhận truy vấn từ tên miền Frontend đã cấp phép (localhost:5173). Ngăn chặn tấn công Cross-Origin Request Forgery (CSRF).
Chống gian lận ODO & Bảo hành Sổ bảo hành điện tử chính hãng 36 tháng khóa chặt theo Số khung & Số máy; ODO chỉ được cập nhật tăng dần qua biên bản nghiệm thu xưởng có chữ ký KTV. Ngăn chặn tua đồng hồ km và gian lận quyền lợi bảo hành miễn phí.

4.2.2 Kế hoạch sao lưu và phục hồi CSDL tự động (Disaster Recovery Plan)

Áp dụng nguyên tắc sao lưu RPO ≤ 1 giờ và RTO ≤ 15 phút với quy trình tự động hóa đã được cấu hình trong Windows Task Scheduler:

⚙️ BẢNG ĐIỀU KHIỂN TÁC VỤ SAO LƯU TỰ ĐỘNG (WINDOWS TASK SCHEDULER) ● STATUS: READY (ĐÃ KÍCH HOẠT)
Tên tác vụ tự động: MotoShopCRM_AutoBackup_Daily
Lịch chạy ngầm: 23:00 hàng ngày (Ngoài giờ làm việc của đại lý xe máy)
Kịch bản thực thi: powershell.exe -ExecutionPolicy Bypass -File D:\crm-project\scripts\Backup_Database_Auto.ps1
Thư mục lưu trữ: D:\crm-project\backup\CRM_XeMayPhuTung_AutoBackup_YYYYMMDD_HHMMSS.bak
Chính sách lưu trữ (Retention): Tự động quét và xóa sạch các bản sao lưu cũ quá 30 ngày để chống tràn ổ cứng.
Phục hồi nhanh khi sập: Chạy file scripts\Restore_Database_Latest.bat → CSDL phục hồi 100% trong 5 giây.
